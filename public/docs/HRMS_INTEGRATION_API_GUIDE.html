HRBP Candidate Data Synchronization & Onboarding Integration API Documentation

1. ภาพรวมระบบ (System Overview)

เอกสารฉบับนี้จัดทำขึ้นสำหรับทีมงาน IT / System Integrator / HRMS Developer เพื่อใช้ในการเชื่อมต่อดึงข้อมูลผู้สมัครงานที่ผ่านการคัดเลือก (Finalized Candidates) และไฟล์แนบทั้งหมดจากระบบ HRBP Recruitment Dashboard ไปยังระบบ IDMS / HRMS ภายในองค์กรเพื่อออกรหัสพนักงานใหม่และเตรียม Onboarding

1
HR อนุมัติส่งตัว
HR ตรวจเอกสารครบถ้วน และกดปุ่ม "ส่งข้อมูลไป HRMS" ในหน้าผู้สมัคร
2
IT ดึงข้อมูล Export
ระบบ IT เรียก Export API ดึง JSON และ Presigned URLs ของไฟล์แนบ
3
ดาวน์โหลดไฟล์
ระบบ IT โหลดเอกสารแนบเก็บเข้าเซิร์ฟเวอร์ และออกรหัสพนักงาน
4
ส่ง Callback Ack
ระบบ IT ยิง Ack Callback ส่งรหัสพนักงาน (EMP ID) กลับมาอัปเดต

2. การยืนยันตัวตนและความปลอดภัย (Authentication & Security)

ทุก Request ที่ส่งมายังระบบ HRBP จะต้องแนบ Secret Key ผ่าน HTTP Header เพื่อความปลอดภัยตามมาตรฐาน PDPA:

X-API-Key: YOUR_ENTERPRISE_SECRET_KEY Content-Type: application/json
🔒 ข้อกำหนดด้านความปลอดภัย (PDPA Compliance):
- ไม่อนุญาตให้เปิด Public API โดยไม่มี Header ยืนยันตัวตน (หากไม่มี Key ระบบจะส่งกลับ 401 Unauthorized)
- ลิงก์ดาวน์โหลดไฟล์แนบเป็น Presigned Secure URLs มีอายุจำกัด 2 ชั่วโมง (7,200 วินาที) ดังนั้นระบบ IT ควรดาวน์โหลดและจัดเก็บเข้า File Server ภายในทันที

3. Endpoint 1: ดึงข้อมูลผู้สมัคร (Export API)

ใช้สำหรับดึงข้อมูลประวัติผู้สมัครและ Presigned URLs ของเอกสารแนบทั้งหมด

GET /api?route=hrms-export

พารามิเตอร์ (Query Parameters):

Parameter Type Required คำอธิบาย
application_id UUID Optional ระบุรหัสใบสมัครเฉพาะเจาะจง เช่น 33656a06-96dd-41c2-a42f-094c834c19c0 [แนะนำ]
status String Optional ระบุสถานะ เช่น READY_TO_SYNC สำหรับตั้ง Cron Job ดึงคิวทั้งหมดเป็น Batch
national_id String Optional ค้นหาด้วยรหัสบัตรประชาชน 13 หลัก
limit Number Optional จำนวนรายการสูงสุดต่อรอบ (ค่าเริ่มต้น: 50, สูงสุด: 100)

ตัวอย่าง Request (cURL):

curl -X GET "https://<DOMAIN>/api?route=hrms-export&status=READY_TO_SYNC" \ -H "X-API-Key: YOUR_ENTERPRISE_SECRET_KEY" \ -H "Content-Type: application/json"

4. Endpoint 2: ส่ง Callback ยืนยันผล (Acknowledgment API)

เมื่อระบบ IT นำเข้าข้อมูลสู่ IDMS/HRMS และออกรหัสพนักงานสำเร็จ ให้เรียก API นี้เพื่อยืนยันสถานะกลับมายัง HRBP

POST /api?route=hrms-ack

Request Body (JSON Schema):

Field Type Required คำอธิบาย
application_id UUID Required รหัสใบสมัครผู้สมัคร (จากฟิลด์ application_id ที่ได้จาก Export API)
hrms_employee_id String Required รหัสพนักงานใหม่ที่ออกโดยระบบ HRMS/IDMS เช่น EMP-69042
sync_status String Optional สถานะการ Sync: SYNCED (สำเร็จ) หรือ FAILED (ไม่สำเร็จ)
notes String Optional บันทึกช่วยจำ หรือ Error Message หากนำเข้าไม่สำเร็จ

ตัวอย่าง Request Body:

curl -X POST "https://<DOMAIN>/api?route=hrms-ack" \ -H "X-API-Key: YOUR_ENTERPRISE_SECRET_KEY" \ -H "Content-Type: application/json" \ -d '{ "application_id": "33656a06-96dd-41c2-a42f-094c834c19c0", "hrms_employee_id": "EMP-69042", "sync_status": "SYNCED", "notes": "นำเข้าข้อมูลสู่ระบบ IDMS สำเร็จโดยระบบอัตโนมัติ" }'

ตัวอย่าง Response:

{ "success": true, "message": "HRMS sync status updated successfully", "data": { "id": "33656a06-96dd-41c2-a42f-094c834c19c0", "full_name": "นาย สมชาย ใจดี", "hrms_sync_status": "SYNCED", "hrms_employee_id": "EMP-69042", "hrms_synced_at": "2026-08-27T18:35:00.000Z" } }

5. การจัดการกรณีพนักงานเก่า (Re-hire Handling)

ในกรณีที่ผู้สมัครเคยทำงานในองค์กรมาก่อน หรือเคยมีประวัติการสมัครในอดีต ระบบ HRBP จะระบุ Flag "is_rehire": true ใน Object rehire_meta ให้โดยอัตโนมัติ เพื่อให้ทีม IT สามารถนำ national_id ไปเชื่อมโยงประวัติบุคคลเดิมในฐานข้อมูล HRMS และออกรหัสพนักงานใหม่ตามนโยบายขององค์กรได้ทันที

6. ตารางรหัสสถานะ HTTP (Status Codes)

Status Code คำอธิบาย
200 OK ดำเนินการสำเร็จ ข้อมูลถูกต้อง
400 Bad Request ส่ง Parameter หรือ Body ไม่ครบถ้วน (เช่น ขาด application_id)
401 Unauthorized ไม่ได้ส่ง X-API-Key หรือ Secret Key ไม่ถูกต้อง
404 Not Found ไม่พบข้อมูลใบสมัครที่ระบุในระบบ
500 Internal Error เกิดข้อผิดพลาดภายในระบบเซิร์ฟเวอร์
